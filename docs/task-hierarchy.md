# Task hierarchy (iPhone/iPad build 58, Mac build 49)

Canvas task trees use `metadata.parent_task_id` for nesting. Direct children share an indented column below their parent; grandchildren occupy the next column, and the next sibling starts after the complete preceding subtree. Solid elbow connectors travel between cards. Dashed dependencies (`metadata.predecessor_task_ids`) remain separate and never change a child's parent or indentation. Collapsed branches, dependency-only components, cycles and projection bounds retain deterministic placement. Rendering never repairs or rewrites relationships.

The shared task detail screen shows its parent, direct children with status and navigation, expandable descendants, and Add subtask. Counts are direct children, including archived tasks, rather than all descendants or dependency successors. Creation uses the existing durable task write queue and metadata contract, with the parent's channel fixed. Pending and failed additions remain visible. Child details link back to the parent; unavailable parents are labelled rather than guessed.

Each expanded parent drains Tower's existing authorized `/tasks/:id/relationships` pages through the sync scheduler. Task records and per-parent relationship membership, completeness, restricted status and refresh time are stored locally. Completed lists filter stale cached membership without deleting or reparenting records. Authorized task upserts and write acknowledgements update known membership atomically, so new children appear through store observation even when the device and server clocks differ. Completeness-only updates emit store changes too.

Unloaded, cached, partial, failed, locked/offline and restricted states are distinguished. An uncertain count carries `+`; restricted results never claim to enumerate inaccessible tasks. Refresh, reopen, identity unlock, task events and a minute foreground fallback reconcile relationships. Each nested expansion loads its own direct list; cycles stop recursive expansion. Canvas refresh failures retain saved tasks with an explicit incomplete-cache warning. Tree projection and loading budgets can truncate large canvases; task details paginate the direct list independently.

Validation uses generic fixtures: six siblings, deep/nested subtrees, mixed dependencies, a dependency discovering a child before its parent, collapse, deterministic large-tree bounds, paginated detail loading, archived children, dependency exclusion, complete membership replacement, failed pages/restricted responses, clock-skew-independent live membership and queued creation metadata. The simulator detail workflow covers creation, immediate list updates, parent navigation and nested expansion; the existing canvas interaction check covers choosing a root and adding/opening a child. Test fixtures do not establish authenticated acceptance on a physical device. Release-specific build, push and installation evidence belongs on the task or in ignored handoffs.
