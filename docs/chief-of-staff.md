# Ambulando Chief of Staff & Living Topic Reference (Mac / Swift Core)

Ambulando owns the Chief of Staff workspace assignment, private owner+agent topic ontology, evidence links, durable corrections, and job status formats on top of existing Ambulando-app-bound NStack Files with `base_version_id` CAS (`409 stale_base_version`). No bespoke NStack endpoints or client-held app keys are added.

## Architecture & ownership

- **Shared Swift Core (`AmbulandoCore/Sources/AmbulandoCore/ChiefOfStaff/`):**
  - `ChiefOfStaffModels.swift`: v1 wire contract (`ambulando.chief_of_staff` assignment channel + per-assignment-epoch `ambulando.chief_of_staff.ontology` private cohort), plaintext envelope adapter seam (`envelope_version = 1`, `encryption.mode = "none"`), `ChiefOfStaffRuntimeBinding`, authoritative server provenance and explicit-permission ACL verification, deterministic durable correction replay, topic search, and strict viewer-own 2-party DM resolution.
  - `ChiefOfStaffService.swift`: `SyncEngine`-coalesced reads, `LocalContentSnapshot` boundary-bound encrypted local cache (no private ontology prose cached in shared assignment state), CAS assignment/correction writes with readback SHA-256 verification, and narrow NIP-98 signed Autopilot generic pipeline invocation (`POST /api/pipelines/definitions/:reconcile_pipeline_id/runs`) when `runtime_binding` is present.
- **App state & Mac UI (`Ambulando/App/ChiefOfStaffModel.swift`, `Ambulando/Views/ChiefOfStaffViews.swift`):**
  - `Manage Workspace → Chief of Staff`: manager selection/change/removal of an existing workspace agent (`kind == "agent"`), ordinary-member read-only view, separate index/schedule status (`Unassigned`, `Assigned · Index setup pending`, `Scheduled`, `Running`, `Healthy`, `Error`, `Disabled (stale assignment)`, `Private index (Owner & Agent)`), and explicit authority & encryption-deferred transparency.
  - Sidebar pinned shortcut: viewer-specific 2-party DM (`{viewerNpub, assignedNpub}` in the DM scope only; never another member's DM, self-DM, or group DM), plus a Topics shortcut for authorized cohort principals (owner or assigned agent).
  - `ChiefOfStaffTopicsView`: searchable topic reference with native evidence navigation (`task`, `doc`, `file`, `thread`, `message`/`audio_note`) and durable CAS corrections (`rename`, `merge_topics`, `archive_topic`, `pin_evidence`, `reject_evidence`).

## Security & provenance invariants

1. **Ordinary-member reads without admin inventory:** Non-managers read `Chief of Staff.assignment.json` with `verifyAcl = false`, never calling `/groups` or `/grants`. Provenance is verified against NStack server `file.created_by_actor_id` and `current_version.created_by_actor_id` (or `file.updated_by_actor_id`) using `/members`: the verified `workspace_owner_npub`, or NStack's server-computed `member.authority.can_manage_workspace` (only a JSON `true` counts). A missing value (older server), `false`, a string or a number all fail closed for delegated managers. Membership role labels such as `owner`/`admin`/`agent` are never treated as authority.
2. **Private cohort isolation:** Non-owner/non-agent viewers receive `.restricted` immediately with zero network calls. Authorized reads verify strict 2-actor grants (owner + assigned agent only, zero groups, zero extra principals) both before and after reading bytes, plus `is_public == false` and SHA-256 verification.
3. **No new source authority & deferred encryption:** Assigning a Chief of Staff grants no new workspace permissions and preserves normal `@` mentions. Encryption is deferred in v1 (`encryption.mode = "none"`); the UI never claims payloads are encrypted today.
4. **Runtime schedule reconciliation:** `runtime_binding` in the trusted assignment JSON has `autopilot_origin` (a clean HTTPS origin: no credentials, path, query or fragment), `reconcile_pipeline_id`, optional `ontology_pipeline_id`, `owner_npub`, `workspace_id`, `agent_npub` (required and equal to `assigned_npub`), a required UUID `subscription_id`, and optional `cron_expression`/`timezone`. Unknown fields are preserved verbatim, both in the binding and at the top level of the payload. Legacy aliases (`autopilot_base_url`, `bot_npub`) are not accepted. Saving for the bound agent sends a run request to Autopilot's existing generic run route. An unprefixed `/api/pipelines/definitions/:id/runs` resolves the definition in the *signer's* own Autopilot space, and the Chief of Staff definitions are installed in the workspace owner's space. The route is chosen from the public key of the identity that actually signs the NIP-98 request, never from a viewer label. When that key is the binding's `owner_npub`, the Mac uses `POST /api/pipelines/definitions/:reconcile_pipeline_id/runs`. A delegated manager (any other signer) uses `POST /api/owners/:owner_npub/pipelines/definitions/:reconcile_pipeline_id/runs`, where the owner is taken only from the verified binding; a binding whose owner is not this workspace's verified owner is refused before any request. The transport allowlist accepts exactly these two run shapes (valid npub, safe definition id) and no other owner-space route. Requests use `mode: wait`, idempotency key `chief-of-staff:reconcile:<workspace>:rev:<revision>:<agent|unassigned>`, and are NIP-98 signed, with no redirects and no app header. The result is read from the Autopilot RunEnvelope's `result.reconciled.schedule_state`: `pending` means honestly pending, `error` means an error, and a `202` means accepted while still running. On a change or removal, the prior binding only requests stale-schedule cleanup, **without** its `subscription_id`, so it can never create a job for the new agent. A new agent stays at `Assigned · Index setup pending` until a binding is provisioned for it.

## Platform status

- **Shared fixture:** `AmbulandoCore/Tests/AmbulandoCoreTests/Fixtures/chief-of-staff-assignment-runtime-binding.v1.json` is byte-identical with the Android/engine copy (`scripts/chief-of-staff/fixtures/assignment-runtime-binding.v1.json`). Its identities are synthetic.
- **Mac:** The shared Swift core, unit tests and Mac UI are implemented and compiled locally. Pete pulls GitHub `main` and builds it on his MacBook for live verification. Source build 153 adds the owner-space run route for delegated managers.
- **Live authority:** NStack's `/members` now returns `authority.can_manage_workspace` for every listed member. It reports the member's *current* effective `workspace.manage` permission, not a historical write-time attestation. A record written by a manager who later loses that permission therefore stops verifying. Older servers omit the field, and the client then fails closed for delegated managers.
- **iPhone:** Shared SwiftUI views use iOS guards; a separate iPhone build and layout/navigation validation remain tracked separately.
