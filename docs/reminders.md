# Personal Reminders

Mac source build 150 adds **Remind me** to message menus (including right click and the native action menu) and the conversation header menu. Selecting it saves immediately and shows the result. A successful save offers **Open task**. Failures offer a retry of the retained request; the app does not report success just because a request was queued.

Mac source build 154 changes **Reminders**, permanently above the sidebar’s workspace/channel lists, to an immediately opening local list in the **current workspace**. It includes only the signed-in human viewer’s New, Ready and In Progress tasks. The existing private Note to Self channel is first, followed by a divider and other assigned tasks across accessible channels/scopes. Empty sections explicitly describe saved open tasks. Saved rows appear while updates run in the background; refresh failures retain the saved list. A cold cache identifies missing local identity/content rather than blocking navigation on discovery. There is no timer or notification schedule.

The list reads the existing partitioned store without the general list’s 500-row limit, respects active accessible channels/scopes and deleted/revoked record states, and recognizes the canonical primary and relational assignments. Pending assignment/status writes use the shared task projection before filtering. Reassignment or status changes remove rows immediately; failed writes roll back and remain visible in the list’s change feedback and task details. List rows open the original task detail/actions. Lock hides saved task rows; workspace/signer boundary changes reconstruct the destination. An agent signer is never substituted for the workspace owner or treated as the human viewer.

Task details use a shared avatar-backed assignee typeahead over the existing authorized workspace member directory (people and agents). Profile display names, cached pictures and fallback initials reuse the existing services. Type to filter, use Up/Down to highlight and Return to stage a selection, then Save. Cancel/Escape writes nothing; Unassigned stages removal. Save uses the existing single-assignee durable write and row-version conflict behavior. Searching does not create a second assignment system.

Saving a reminder still requires an existing active `kind: dm` channel whose exact `participant_npubs` array contains only the signed-in human. Names do not establish ownership. Missing or ambiguous boards are reported without creating channels or changing grants. The current member must be a human; the app never substitutes an agent identity. Source messages are freshly read through the signed message route before saving. Native source links resolve the original message through its signed ACL route, including when it is absent from the local cache; a missing, mismatched or inaccessible source is refused. The original conversation opens at the selected message using the existing reading-position anchor.

Tasks use the chat title, trimmed and limited to 200 characters; a missing title falls back to the message’s first nonblank line, then “Saved conversation”. The raw selected message body retains its formatting and links, followed by `Source: @[Original message](mention:chat:<channel>#<message>)`. Header actions use the root message. Tasks are Ready, priority sand, assigned to the human, and carry `metadata.ambulando_reminder` version 1 with source channel/message, optional source thread and message row version. A source thread ID is not attached as the task’s own thread in the private channel.

The client uses the existing task-create route and actor/workspace-scoped `client_request_id` contract. Before sending, it persists and reads back the complete frozen request and destination using the existing identity-sealed local snapshot storage. Its slot includes account, backend, app, workspace and source identity. Repeated saves on the same installation reuse the exact request, including after an interrupted response or app relaunch. A changed destination is refused. Concurrent taps share an in-flight guard. Another device’s independent save may create a separate task; global cross-device deduplication is not promised. Explicitly clearing local workspace data removes this retained request history.

Mac validation uses deterministic core tests and a local Xcode build. This does not establish installation or authenticated acceptance on Pete’s MacBook. Shared native views also expose this flow to iPhone/iPad, but mobile build/device acceptance and web parity remain separate work.

The isolated Mac Test app also checks the actual rendered reply menu through AppKit, the reminder sheet and task persistence. Its seeded root and reply have different bodies and IDs. The task must contain the reply's exact body, provenance ID and native source link; the header must still save the root. After building `AmbulandoMacTest`, run its executable with `-AmbulandoFixtureDMs -AmbulandoMacThreadRegression -AmbulandoMacChatLinkCheck -AmbulandoMacReminderIdentityCheck`. Add `-AmbulandoMacReminderRootFault` to install the actual root menu callbacks on the reply button: this deliberate test fault must exit nonzero at the selected source ID assertion. The check uses an isolated synthetic account, never a live human account. The native row menu and SwiftUI context menu share the row's reminder state and `ReminderSheet(message: message, ...)`; the context-menu gesture itself is not automated by this check.

The Mac performance/interaction regression uses the isolated Test app with `-AmbulandoFixtureDMs -AmbulandoMacThreadRegression -AmbulandoMacRemindersCheck`. It seeds authorized local tasks before delaying transport, measures the actual sidebar click and first populated row, and checks offline navigation, existing detail identity, avatar typeahead, assignment persistence and live changes. Core `ReminderListTests` checks viewer/state/relational assignment boundaries, lifecycle exclusions, a match beyond 500 unrelated tasks, workspace isolation and channel revocation. These synthetic checks do not establish real-account acceptance or MacBook installation. iPhone/iPad shared-source parity still needs its separate nightly build/device validation; web remains separate.
