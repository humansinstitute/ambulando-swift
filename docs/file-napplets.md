# File-backed daily tracker

Apps → Daily Metrics opens a private tracker directly, without Artefacts navigation or source/history controls. A complete remote metadata search in the signed-in viewer’s self-DM adopts the existing tracker, offers a chooser for multiple instances, or offers explicit first-run setup when none exists. Failed, denied, invalid or incomplete discovery never enables replacement setup. Setup rechecks discovery before provisioning; an uncertain attempt is recorded on the device and requires reconciliation before another attempt. No cross-device atomic singleton is claimed. The app reuses or creates that viewer's self-DM and privately uploads a JSON data File and the reviewed HTML template as a separate File. Opening executes the exact saved HTML version, after explicit trust and data-use confirmation, remembered on this device for unchanged verified code and bound access. No data is imported and no sample health records are created. Code and entries remain NStack Files with normal channel ACLs; authorized administrators and storage operators may access them.

Existing Artefacts, chat File references and personal File pins open the same saved File. Ordinary HTML stays bridge-free. Installed org-data napplets retain their separate contract; canvas HTML does not gain data access.

The File bridge admits the daily-tracker-v1 format and one host-owned tracker binding. Messages contain only read, save or dirty intent, an exact per-document nonce and request ID. An opaque script-only iframe, nonpersistent WebKit storage, CSP, network blocking, navigation rejection and native frame checks isolate code. The frame receives no key, signer, URL or arbitrary request interface.

Every read reauthorizes the code File, bound data File and its self-DM participants. Current version metadata comes from a bounded limit=1 history request; exact bytes must match MIME type, length and SHA-256. The host validates metric types, limits, calendar dates and references, retaining false and zero separately from missing answers. Used definitions cannot disappear or change type. Saves privately upload JSON and publish with the original base_version_id; success requires current-version readback. Conflicts preserve the original draft and require explicit reload. Uncertain outcomes are read back, never blindly retried against a newer base.

Tracker values and unsaved drafts remain in memory; native SQLite, source recovery files and localStorage are not their system of record. Foreground, shared invalidations and a 30-second visible timer reauthorize access while preserving the mounted document. Failed authorization, account/workspace/backend changes, close, pagehide or self-navigation destroy the frame. Pending authorization hides content and rejects writes. Pending saves block voluntary close, including the Mac main window’s red close button and Cmd-W. Canceling the unsaved-changes prompt keeps the mounted document and draft intact. Close, reload, source/history and normal section/sidebar navigation guard unsaved work. Source/history removes the bridge; reopening rechecks current code, binding and access before consulting device-local approval. Changed bytes or access need new consent. Forced access or identity loss discards memory drafts.

The packaged template in Resources is a byte-identical copy of the shared browser bundle. It is used only for explicit provisioning, then fetched from NStack at runtime. Update it only from the coordinated final package and verify its SHA-256 across hosts.

Local validation includes core model/transport tests and the isolated Mac Test app's `-AmbulandoMacThreadRegression -AmbulandoMacFileNappletCheck` check. The latter executes the packaged UI in the production opaque WebKit host at phone width with synthetic in-memory data only. Local builds and synthetic tests do not establish installation, TestFlight availability or authenticated acceptance on physical devices.

The focused Mac `-AmbulandoMacThreadRegression -AmbulandoMacFileNappletCloseCheck` regression exercises AppKit close actions, exact DOM draft retention, a suspended bridge save, explicit discard and forced context-loss teardown. It targets a native Cmd-W menu at the test window so it can run without global keyboard focus; physical-keyboard routing and installation on another Mac remain device acceptance checks.

The canonical logical app link is `/flight-deck?workspaceid=<workspace UUID>&napplet=daily-tracker`. Supported relative in-app links and links on the connected Tower origin resolve only within the selected workspace; other HTTPS origins retain browser handling. Native does not add an OS universal-link association or assume a separate frontend domain. The route contains no private File IDs or data. Toolbox keeps Daily Metrics available even when its device-local Apps placement is hidden; show/hide and first/last order are partitioned by connection, server, viewer and workspace. Existing WApp ordering and management remain unchanged.

The isolated Mac `-AmbulandoMacDailyMetricsAppsCheck` check exercises the visible phone-width launcher, placement, direct routing and navigation gate, then runs the existing real WebKit synthetic tracker check. Core discovery tests cover metadata adoption, repeated reads without provisioning, multiple candidates, incomplete listing, invalid metadata, denied access, wrong viewer and corrupted data.

Consent receipts use policy v1 and bind normalized backend origin, connection and available Tower service identity, viewer signer, workspace/app namespace, code File ID, SHA-256 of the exact verified HTML bytes, manifest version/app ID, tracker binding name and exact data File ID, format/privacy, sorted read/save operations and fresh effective write access. Data values, data revisions and code revision IDs are excluded, so ordinary daily edits and identical-byte code revisions do not prompt again. Receipt matching never replaces signed authorization: code, binding and data access are checked before matching on every open, again on explicit approval, and on bridge operations. A read-only approval cannot acquire write access within the running session.

Receipts stay in the native app container's Application Support/<bundle-id>/NappletTrust directory, excluded from backups, with no server or ubiquitous synchronization. Missing, malformed, mismatched or unreadable receipts fail closed. A failed remember operation allows only the explicitly approved open session and displays a notice. “Forget approval” remains visible in the running app controls, respects dirty-draft confirmation and pending saves/checks, removes only consent, and returns to the prompt without deleting tracker Files. Canceling discard keeps the existing document and receipt. Approval is separate on every device; rebuilding/pulling source does not install or verify it on another Mac.

The opt-in `-AmbulandoFixtureNappletTrust` signed synthetic Tower boundary supports production iPhone/Mac consent UI checks. `-AmbulandoMacThreadRegression -AmbulandoMacNappletTrustCheck` exercises initial consent, reload/reopen, revoke, code/binding/access changes, denied access and unavailable receipt storage, then runs the existing packaged WebKit tracker regression. `NappletTrustUITests` covers the iPhone consent path, process restart and guarded revoke. These are synthetic local checks, separate from physical-device acceptance.

Source versions: Mac 0.1.0 (104), iPhone/iPad 0.1.0 (105).
