# Parity matrix: Ambulando web (sol) → native iPhone

This table shows which Ambulando web features exist natively today, which work
package (WP) delivers each one, and which will stay web content or out of scope.
It is updated at every package handoff. The Status column states only what has
evidence behind it.

Status values (this file is updated only after validation evidence exists):

- **Delivered:** implemented and tested. The "Evidence" column says whether that
  means unit tests, the simulator or a live backend.
- **Planned:** scheduled in the named package and not started.
- **Web content:** the record itself is an HTML document (for example an HTML
  artefact or a WApp's own UI). An HTML artefact opens in a labelled, sandboxed
  web view; a WApp or artifact page opens as an in-app browser tab (build 13).
  The surrounding navigation stays native, and it is not counted as native parity.
- **Proposed later package / proposed deferral:** this is the worker's proposed
  scope, not a decision Pete has approved. These items are not excluded
  permanently, and none is treated as web by default.
- **Unsupported:** needs a platform or server capability that does not exist.

### Native Deck composition and document selection

Deck’s Inbox plus opens a new-thread composer immediately, with its channel picker inside. Cancel preserves the
channel draft; Send uses the durable outbox and opens the exact acknowledged thread over Deck, keeping the card/context.
An empty context shows an explanation without a send control.

On iPhone/iPad, every document route opens its formatted page for editing when the stored format is editable. Comments
open beside that editing session in a sheet. Long-press a passage, choose Select if needed, then **Comment on selected
text**. The range is captured before the sheet takes focus; any document edits must save successfully before the anchor
is attached to the canonical version. Quotes reopen their passage after reload. Rich selections use web ProseMirror
UTF-16 positions; Markdown uses source lines/quotes. Unknown formats stay in the read-only renderer. Tower retains edit
lease, permission and version enforcement; a local draft does not grant write access. Mac keeps its existing inline Edit
and native reader selection flow; no shared API or web/backend changes are required.
